Technical Specifications

Ghost-Tag v2.1.0 is an offline, client-side encrypted NFC storage system. It fragments, encrypts, and distributes data across physical NFC chips using a canonical NDEF binary envelope format.

Canonical Binary Envelope Layout

MAGIC (4B: "GTAG" [0x47, 0x54, 0x41, 0x47]) FORMAT_VERSION (1B: 0x02) RECORD_TYPE (1B: 0x01 Single | 0x02 Bulk) VAULT_ID (16B CSPRNG) FILE_ID (16B CSPRNG) KEY_ID (16B CSPRNG) GLOBAL_CHUNK_INDEX (4B Little-Endian) TOTAL_VAULT_CHUNKS (4B Little-Endian) FILE_CHUNK_INDEX (4B Little-Endian) TOTAL_FILE_CHUNKS (4B Little-Endian) CIPHERTEXT_LENGTH (4B Little-Endian) CHUNK_HASH (32B SHA-256) AES_GCM_NONCE (12B CSPRNG) ENCRYPTED_CHUNK (Variable Length Ciphertext) AES_GCM_AUTH_TAG (16B Authentication Tag)

MIME Types & Framed Chip Capacity

  • Single-Tag MIME Type (v1): application/vnd.ghost.secure (28B MIME string; 54B fixed envelope overhead: 26B AAD + 12B nonce + 16B GCM tag).
  • Bulk Distributed MIME Type (v2): application/vnd.ghost.bulk (26B MIME string; 134B fixed envelope overhead: 74B AAD + 32B SHA-256 CHUNK_HASH + 12B nonce + 16B GCM tag).
  • NDEF Framing Overhead: NFC Forum Type 2 NDEF TLV framing (0x03 length + 0xFE terminator + 4B page alignment) and NDEF MIME record headers (31B/34B for v1, 29B/32B for v2) further reduce usable payload space below raw chip EEPROM.
  • NTAG213 Compatibility: Supports v1 single-tag envelopes only (52B conservative mobile / 56B exact bridge framing). It cannot fit a v2 bulk envelope (0B usable, fits: false); NTAG215 or NTAG216 tags are required for v2 bulk vaults.

Cryptographic Security Model

Ghost-Tag operates under a zero-trust model where physical NFC chips may be inspected, cloned, or lost without revealing plaintext data.

  • Authenticated Symmetric Encryption: AES-256-GCM with unique 96-bit CSPRNG nonces per chunk.
  • Key Derivation Function: RFC 9106 Argon2id (16 / 32 / 64 MiB primary tiers on native; vendored offline hash-wasm Argon2id WASM m=32768, t=3, p=2 for cross-platform recovery auth/verifier, with WebCrypto PBKDF2 local KEK compatibility where applicable).
  • Two-Tier Hierarchy: Key Encryption Key (KEK) unwraps ephemeral Data Encryption Keys (DEKs) in volatile memory only.
  • Zero Secrets Policy: Master passphrases, raw KEKs, and decrypted plaintext are never persisted to disk or cloud storage.
  • Supabase Cloud Role: Supabase stores exclusively an encrypted vault metadata blob for cross-device account restoration; it never receives keys, plaintexts, or NFC data.

Privacy & Zero-Knowledge Guarantees

Ghost-Tag enforces absolute user privacy by design:

  • Zero Telemetry: No analytics scripts, no tracking pixels, no telemetry beacons.
  • Zero Cookies: The web client does not set tracking cookies or third-party cookies.
  • No Scanned-Chunk Cache: Scanned NFC chunks reside purely in volatile session memory during active transactions and are purged immediately upon session completion.
  • Encrypted URLs by Default: Web links stored on Ghost tags are encrypted binary ciphertext; they do not open as readable NFC URL records.
