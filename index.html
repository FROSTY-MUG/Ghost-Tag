Ghost-Tag Technical Specifications

Ghost-Tag v2.0.5 implements zero-knowledge encrypted physical storage across NFC Forum tags.

Cryptographic Envelope Layout

Every NFC tag contains a canonical binary envelope bound via Additional Authenticated Data (AAD):

MAGIC (4B: "GHTG") FORMAT_VERSION (1B: 0x02) PURPOSE (1B: 0x01 Single | 0x02 Bulk) KEY_ID (16B CSPRNG) CIPHERTEXT_LENGTH (4B Little-Endian) IV / NONCE (12B CSPRNG) AUTH_TAG (16B AES-GCM) CIPHERTEXT (Encrypted Payload)

Key Derivation & Memory Security

  • Argon2id / PBKDF2-SHA256: 100,000 iterations over 32-byte CSPRNG salt.
  • AES-256-GCM: Authenticated encryption with 96-bit fresh random nonces per write.
  • Zero-Secrets Invariant: No passphrases, KEKs, DEKs, or plaintext stored in cookies, localStorage, or server logs.

Erasure Coding & Partitioning

  • Cauchy Reed-Solomon GF(2^8): Deterministic recovery of $K$ data chunks from any $K$ out of $N$ tags in arbitrary order.
  • MIME Types: application/vnd.ghost.secure, application/vnd.ghost.bulk.

Security Invariants

Ghost-Tag operates exclusively client-side. There are no user accounts, no cloud endpoints, and no remote telemetry. If you discover a cryptographic vulnerability, report it confidentially to aryanarora26110@gmail.com.

Privacy Policy

Zero telemetry. Zero cookies. Zero server sync. All encryption, NFC writing, and recovery phrase derivations occur purely in local volatile memory.
